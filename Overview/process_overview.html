📅 Weekly Operation (the normal cadence)

Each week, drop the new meeting transcript into input/transcripts/ and run the weekly pipeline. The filename must contain the meeting date (e.g. Electronics AI - Working Session - 6_17_2026.docx).

# 0) one-time per shell on Windows (avoids a Unicode console error)
$env:PYTHONIOENCODING = "utf-8"

# 1) run the full weekly pipeline on the new transcript
python src/main.py --input "input/transcripts/Electronics AI - Working Session - 6_17_2026.docx" --mode weekly

# optional: override the meeting date if it isn't in the filename
python src/main.py --input ".docx" --mode weekly --date 2026-06-17

The weekly mode runs all 12 steps: read → clean → chunk → extract → classify → validate → workbook → payload → HTML report → archive → ingest history → weekly report → refresh monthly rollup.

Back-dated transcripts are handled automatically. If the transcript's date is earlier than any week already in history, --mode weekly detects this and rebuilds all weekly and monthly reports so every longitudinal view stays accurate. You just run the same command — no special flag needed.
Idempotent. Re-running the same meeting date replaces that date's rows in history — it never double-counts. Safe to re-run after fixing a transcript.
Requires an OpenAI key. Steps 4–5 call the model, so set OPENAI_API_KEY in .env. Without a key, use --mock to exercise the wiring, or hand-classify rows.
Closing the loop with Azure DevOps (opt-in). After reviewing output/weeks/<date>/review_rows.xlsx, add --push-ado to the command to create ADO Issues for each approved opportunity. Each subsequent weekly run automatically syncs live ADO status back into all reports — no manual lookups needed.

🤖 Automatic Trigger (folder watcher)

Instead of running the pipeline by hand, run the watcher. It polls input/transcripts/ and auto-runs --mode weekly on any new or changed .docx once its upload has finished.

$env:PYTHONIOENCODING = "utf-8"

# one-time: baseline the files already processed so they are NOT re-run
python src/watch_transcripts.py --mark-processed

# then start watching (Ctrl+C to stop)
python src/watch_transcripts.py

# useful variants
python src/watch_transcripts.py --once         # process current backlog, then exit
python src/watch_transcripts.py --interval 10  # poll every 10s (default 5)
python src/watch_transcripts.py --print-only   # show what would run, run nothing
  • Safe for in-progress uploads — a file is processed only after its size + modified time stay unchanged across one poll.
  • Idempotent — processed files are recorded in output/history/processed_files.json (keyed by name + size + mtime).
  • Each new transcript triggers main.py --mode weekly, regenerating the weekly and monthly reports automatically.

🗓 Monthly Rollup

The monthly report is refreshed automatically at the end of every weekly run. To (re)build it on demand from accumulated history:

$env:PYTHONIOENCODING = "utf-8"

# most recent month present in history
python src/main.py --mode monthly

# a specific month
python src/main.py --mode monthly --month 2026-06

It writes output/reports/monthly_<YYYY-MM>.html with per-week totals, bucket-by-week stacking, signal/level momentum, and a full table of every opportunity active that month.

🛠 Keeping It Running

Weekly checklist

  1. Save the new transcript to input/transcripts/ with the meeting date in the filename.
  2. Confirm OPENAI_API_KEY is set in .env.
  3. Run --mode weekly (or let the watcher do it).
  4. Open output/weeks/<date>/weekly_report.html and review every card — they default to Needs Review.
  5. Correct anything wrong in review_rows.xlsx; only then consider a push.
  6. Push to Azure DevOps only when explicitly approved (--push-ado after review), and push to SharePoint only when explicitly approved (--mode push, with the Power Automate URL configured).

Core rules (do not break)

  • Never send full transcripts to the model — only keyword-filtered chunks.
  • All model output is draft-only; rows default to Needs Review.
  • Human review is required before any SharePoint or ADO push.
  • Never commit secrets; never hard-code the Power Automate URL (read it from config/env).
  • SharePoint internal names come from config/sharepoint_field_mapping.json; allowed values from config/choice_values.json; row shape from config/mvp_output_schema.json.

Report format standard

The weekly HTML must keep the original ai_opportunity_report.html layout and behavior — KPI header plus the 📋 Cards / 📊 Analytics / 🗂 Full Table / 📈 Trends / 🔗 Progress tabs. The canonical layout lives in report_generator.build_report_html() (single source of truth). See skills/weekly_report_format.md before changing any report code.

Adding new weeks over time

  • Just keep dropping transcripts in and running weekly — history accumulates automatically.
  • Recurrence across weeks is detected by deterministic fuzzy title matching (no AI), so trends stay reproducible and token-free.
  • To rebuild a corrupted history, re-run --mode weekly for each transcript in chronological order.
  • To manually force a full report regeneration from current history (e.g. after edits): python src/main.py --mode rebuild

🔗 ADO Integration — Closing the Loop

Identified opportunities only deliver value if someone picks them up and executes. The ADO integration closes the loop between "we discussed this in a meeting" and "someone is actually working on it" by creating tracked Issues in Azure DevOps and surfacing their live status in every report.

Three capabilities

CapabilityWhenWhat it doesOperator action
Step 0 — SyncEvery weekly run (automatic)Reads live ADO status for all previously pushed items and updates archived rowsNone — silent background step
Step 9c — PushAfter human review (opt-in)Creates ADO Issues for new approved opportunities; writes back IDs and URLsAdd --push-ado flag after reviewing xlsx
Progress tabEvery weekly reportShows all ADO-linked items grouped by state (Doing / To Do / Done); highlights state changes in last 7 daysOpen weekly_report.html, click Progress tab

Running an ADO push

# 1) Run the normal weekly pipeline first
python src/main.py --input "input/transcripts/YOUR_FILE.docx" --mode weekly

# 2) Review output/weeks/<date>/review_rows.xlsx

# 3) When satisfied, re-run with --push-ado to create ADO Issues
python src/main.py --input "input/transcripts/YOUR_FILE.docx" --mode weekly --push-ado
Safe to re-run. Title-based dedup prevents duplicate ADO items — if an item with that exact title already exists in ADO, its existing ID is recovered instead of creating a new one.

FieldDescriptionWhen populated

Step 0 is always read-only. The automatic sync at the start of every weekly run never creates or modifies ADO work items. It only reads current state from ADO and updates local files. ADO push is always an explicit operator step.

🚑 Troubleshooting

SymptomCause / Fix
UnicodeEncodeError on → in the consoleWindows cp1252 console. Set $env:PYTHONIOENCODING = "utf-8" first. Generated HTML is unaffected.
Extraction/classification fails or is emptyMissing/invalid OPENAI_API_KEY in .env. Use --mock to test wiring without the model.
Wrong meeting date / week labelFilename date couldn't be parsed. Pass --date YYYY-MM-DD explicitly.
Watcher keeps re-saying "WOULD process"--print-only never writes the manifest by design. Drop the flag to actually process and record.
Duplicate opportunity across weeks not mergingTitles too dissimilar for the fuzzy matcher. Align titles in the source rows; re-run the week.
An opportunity got double-countedRe-run --mode weekly for that meeting date — ingest is idempotent and will replace it.
