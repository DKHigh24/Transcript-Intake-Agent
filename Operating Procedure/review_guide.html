Human Review & ADO Publishing Guide

Electronics AI Working Group  ·  Transcript Intake Agent  ·  Last updated June 2026

1 — What This Is

After the pipeline classifies opportunities from a transcript, nothing gets pushed to Azure DevOps automatically. Every opportunity sits in a Review Queue until a human signs off on it. Only approved items are published.

Weekly Pipeline
--mode weekly
→
Review Queue
--mode review
→
Your Approval
A / R / E
→
ADO Push
--push-ado

This guide walks you through every step of that flow, including how to go back and review older weeks you have not yet published.

📋
What the review captures: Every action you take (approve, reject, edit a field) is written to a log file. Over time this builds up a record of every place the AI got something wrong and how it should have answered — which feeds a controlled classifier improvement cycle described in Section 8.

2 — One-Time Setup

Set your reviewer identity

Open .env in the repo root and add:

# .env
REVIEWER_ID=your.name

This name appears in every feedback log record and in the queue action history. If you skip this, the system falls back to your Windows login name.

✓
No other setup is needed for the review workflow. ADO publishing requires ADO_PAT, ADO_ORG_URL, and ADO_PROJECT in .env — see the Operating Manual Section 9 for ADO setup instructions.

3 — Normal Weekly Flow

1

Drop the new transcript in input/transcripts/

Filename format: Electronics AI - Working Session - M_D_YYYY.docx

The date is parsed automatically from the filename.

2

Run the weekly pipeline

This extracts and classifies opportunities, archives the week, and builds the review queue.

python src/main.py --input "input/transcripts/Electronics AI - Working Session - 6_24_2026.docx" --mode weekly

At the end you will see:

=== Step 5d: Review queue === 8 item(s) pending review -> output/review_queue/2026-06-24/queue.json Run: python src/main.py --mode review --date 2026-06-24
3

Run the review

Walk through each opportunity interactively. Approve, reject, or correct fields before approving.

python src/main.py --mode review --date 2026-06-24
4

Push approved opportunities to ADO

Only rows you approved in Step 3 will be published. Items you rejected or left pending are skipped.

python src/main.py --input "input/transcripts/Electronics AI - Working Session - 6_24_2026.docx" --mode weekly --push-ado

4 — Running the Review in Detail

Start a review session

# Review a specific date
python src/main.py --mode review --date 2026-06-24

# Omit --date to automatically pick the most recent week
python src/main.py --mode review

What you see for each item

TITLE: AI-Assisted Content Organization & Coaching Workflow TYPE: Classification | CONFIDENCE: High MATURITY: In Progress / Piloting | PRIORITY: High EVIDENCE: "We started organizing our onboarding content using Copilot..." PROBLEM: Content is scattered across tools with no single coaching standard [A]pprove / [R]eject / [E]dit field / [K]eep pending / [Q]uit:

Resuming a session

You can press Q at any time. Progress is saved after every action. Run the same command again to pick up where you left off.

[review] Session summary for 2026-06-24: Approved : 5 Rejected : 1 Edited : 2 Skipped : 1 Still pending: 1 Run --mode review --date 2026-06-24 again to continue.

5 — Review Actions

Key Action What happens
A Approve Marks the opportunity as reviewed and ready to publish. You can add an optional note. The item will be pushed to ADO the next time you run --push-ado.
R Reject Removes the opportunity from consideration. A reason is required. The item will never be pushed to ADO unless the queue is manually reset.
E Edit field You are prompted for a field name and a new value. The system validates choice fields against the allowed list and tells you if the value is invalid.

After editing, it asks: "Approve now? [Y/N]" — you can approve in the same step or come back later.

The original AI-generated value is always preserved in the _model snapshot inside the row and in the feedback log.
K Keep pending Skips the item for now. It stays in the queue as pending. You can come back to it in the same session or a future one.
Q Quit Ends the session and saves all progress. Nothing is lost.

Editing a field — step by step

[A]pprove / [R]eject / [E]dit field / [K]eep pending / [Q]uit: E Field name to edit: AIUseCaseType Current value: Classification New value: Automation Notes (optional): This clearly creates and triggers a workflow Field 'AIUseCaseType' updated to 'Automation' Approve now? [Y/N]: Y Notes (optional): Approved
⚠
Choice fields are validated against the allowed list in config/choice_values.json. If you enter an invalid value the system will print the allowed options and let you try again — no action is saved until the value is valid.

6 — Pushing Approved Items to ADO

Standard push (only approved items)

python src/main.py --input "input/transcripts/..." --mode weekly --push-ado

The pipeline will:

  • Skip any item with Pending or Rejected status and print a warning
  • Push only Approved items that do not yet have an ADO work item ID
  • Write the ADO item ID, URL, and status back into the archived classified_rows.json
  • Skip items that are already in ADO (title-based dedup — no duplicates created)
=== Step 9c: Push new opportunities to ADO === [ado] 3 row(s) skipped -- not yet approved by reviewer [ado] Run --mode review --date 2026-06-24 to approve items first [ado] Pushed #87: AI-Assisted Content Organization [ado] Pushed #88: Skills / Prompts Repository Maintenance Model

Override the review gate (legacy / bypass)

If you need to push everything regardless of review status — for example when back-filling weeks before the review feature existed — add the --skip-review-gate flag. This emits a prominent warning and pushes all primary rows that don't already have an ADO ID.

python src/main.py --input "..." --mode weekly --push-ado --skip-review-gate
⚠
Use sparingly. --skip-review-gate bypasses the review gate entirely. ADO items created this way will not have reviewer attribution in the feedback log.

8 — The Feedback Loop (Improving the AI Over Time)

Every reviewer action is automatically written to output/feedback/feedback_log.jsonl. Over time this log captures every place the AI got something wrong and how you corrected it. When you are ready to use that feedback to improve future classifications:

1

Generate a staged improvement proposal

Analyses the feedback log and writes proposed prompt rule updates and few-shot examples to a staging folder. Nothing is changed yet.

python src/main.py --mode apply-feedback

Output: config/feedback_staging/v20260625/
Review proposed_rules.md and proposed_examples.jsonl before proceeding.

2

Run the accuracy eval

Runs the current classifier against your labelled examples and produces a pass/fail accuracy report. Requires at least 5 labelled examples in config/eval/examples.jsonl.

python src/main.py --mode eval
3

Promote the staged changes (only if eval passes)

Applies the proposed rules and examples to the live classifier. Blocked automatically if the eval accuracy is below the configured threshold (default: 80%).

python src/main.py --mode promote-feedback --feedback-version v20260625

After promotion, commit the changes to git so the improvement is tracked and reversible.

🔒
No automatic self-modification. The AI never updates its own prompts. Every improvement requires: feedback logged → proposal staged → eval passed → explicit human promotion → git commit. The full history is always in version control.

9 — Quick Reference

All commands at a glance

CommandWhat it does
--mode weekly Run the full pipeline, build the review queue. Does NOT push to ADO.
--mode review Interactive review CLI. Approve, reject, or edit opportunities before publishing.
--mode weekly --push-ado Re-run pipeline and push only approved items to ADO.
--mode weekly --push-ado --skip-review-gate Push all primary rows regardless of review status (legacy / bypass).
--mode apply-feedback Build a staged improvement proposal from the feedback log.
--mode eval Run the classifier against labelled examples and report accuracy.
--mode promote-feedback --feedback-version <v> Apply staged changes to the live classifier after eval passes.
